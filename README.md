# Enterprise FYC Movie Intelligence System

A Python CLI-based Retrieval-Augmented Generation (RAG) system that uses specialized AI agents to answer qualitative and quantitative questions about a movie studio's "For Your Consideration" (FYC) awards campaign policies and movie database. The system runs entirely locally — no cloud infrastructure required.

## Architecture

The system is built around three coordinating agents:

**Manager Agent** (`agents/manager.py`) is the entry point for every query. It sends the user's question to Gemini with a routing prompt and receives back a classification of `QUALITATIVE`, `QUANTITATIVE`, or `HYBRID`, along with any sub-queries needed for each downstream agent. For qualitative or quantitative routes, it simply delegates to the relevant agent and returns the result. For hybrid routes, it calls the Qualitative Agent first, feeds that answer as context into the Quantitative Agent's query, then makes a final Gemini call to synthesize both results into one unified answer that explicitly compares policy standards against database figures.

**Qualitative Agent** (`agents/qualitative_agent.py`) handles document/policy questions. On startup, it reads all markdown files in `data/docs/`, splits them into per-rule chunks, and indexes them into a local ChromaDB collection using Sentence Transformers (`all-MiniLM-L6-v2`) for embeddings — this step runs entirely locally with no API cost. At query time, it performs a semantic similarity search against the collection, retrieves the top-2 most relevant chunks, and passes them as context to Gemini, which is instructed to answer using only that context and to cite the specific rule and document.

**Quantitative Agent** (`agents/quant_agent.py`) handles numeric/database questions. It sends the user's question along with the SQLite schema to Gemini, which returns a raw SQL `SELECT` query. That query is passed through a validation layer (see below) before execution against `enterprise.db`. The resulting rows are then summarized back into a natural-language answer by a second Gemini call.

**Data flow for a hybrid query** (e.g. "Do any films with a budget over $100M meet our FYC campaign rating criteria?"):
```
User Query
  → Manager (routing call to Gemini) → classified as HYBRID
  → Qualitative Agent (retrieves & answers policy question)
  → Quantitative Agent (answers DB question, using policy context)
  → Manager (final synthesis call to Gemini)
  → Unified answer returned to user
```

### SQL Validation Layer

No SQL query generated by the Quantitative Agent is executed until it passes `validate_sql()` (`agents/validate.py`), which:
- Blocks any query containing `DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, or `TRUNCATE`
- Requires every query to start with `SELECT`

This is tested independently in `test_check.py` with 6 passing cases covering valid SELECTs, aggregates, and each blocked keyword.

### Tokenomics Tracking

Every Gemini call across all three agents logs its input/output token count and estimated cost via `log_usage()` in `tokens.py`. Usage is accumulated across a session and can be printed as an aggregate summary — broken down per agent, with total cost and the highest-consuming agent — via `display_output()`.

## Setup

**1. Clone the repo and create a virtual environment:**
```bash
python -m venv .venv
source .venv/bin/activate   # on Windows: .venv\Scripts\activate
```

**2. Install dependencies:**
```bash
pip install -r requirements.txt
```

**3. Add your Gemini API key.** Create a `.env` file in the project root:
```
GEMINI_API_KEY=your_key_here
```

**4. Generate the local data (policy doc + database):**
```bash
python create_data.py
```
This writes `data/docs/awards_policy.md` and creates `enterprise.db` with sample movie records.

## Usage

**Interactive CLI** — ask one question at a time:
```bash
python main.py
```
```
Enter Query > What is the IMDb rating threshold for an FYC campaign?
...
Enter Query > exit
```
Typing `exit` or `quit` ends the session and prints the tokenomics summary.

**Benchmark mode** — runs all 10 predefined test queries (qualitative, quantitative, and hybrid) back-to-back with rate-limit spacing, then prints the final tokenomics summary:
```bash
python main.py --benchmark
```

**Run the SQL validator test suite:**
```bash
pytest test_check.py -v
```

## Supported Query Types

- **Qualitative** — questions answered purely from `awards_policy.md`, e.g. *"What IMDb rating threshold must a movie achieve to qualify for an FYC campaign?"* or *"When does campaign spending require special studio board sign-off according to policy?"*
- **Quantitative** — questions answered purely from `enterprise.db`, e.g. *"Which director has won the most Oscars in our database, and how many did they win?"* or *"What is the average box office collection for films directed by Christopher Nolan?"*
- **Hybrid / complex** — questions that require both the policy document and the movie database together, e.g. *"Based on our FYC campaign policy, do our 1990s films meet our minimum IMDb rating criteria?"* or *"Which movies in our database satisfy both the policy runtime criteria and the 8.5 IMDb rating threshold?"*
- **Content-based routing (red herring) queries** — questions deliberately worded so that keyword matching alone would misclassify them, e.g. *"Do any films with a budget over $100M meet our FYC campaign rating criteria?"* — this requires the Manager to reason about the actual intent (a rating check against policy, not just a budget lookup) rather than routing off the presence of a dollar figure.

**Most tokens consumed by:** Manager — expected, since every query (qualitative, quantitative, or hybrid) pays a Manager routing call up front, and hybrid queries additionally pay for a Manager synthesis call at the end.



The Gemini free tier enforces a hard daily cap (20 requests/day for `gemini-3.6-flash` in this project's configuration) in addition to a per-minute cap. A single hybrid query costs 4-5 Gemini calls (routing, qualitative retrieval, SQL generation, result summarization, and final synthesis), so a full 10-query benchmark — combining qualitative, quantitative, and hybrid queries — exceeds the daily quota in one sitting. To manage this:

- A retry-with-backoff wrapper (`api_utils.py`) was added to automatically absorb per-minute 429 errors.
- The 10 required queries were run and logged across multiple sessions/days rather than one continuous benchmark, with each session's tokenomics output captured as evidence above.
- No workaround (e.g. creating additional accounts or projects) was used to bypass the daily cap, since doing so would violate Gemini's terms of service.

## Notes on Rate Limits

Gemini's free tier enforces both a per-minute and a per-day request cap. `api_utils.py` wraps every Gemini call in a retry-with-backoff handler to absorb per-minute 429 errors automatically. The per-day cap cannot be worked around programmatically — if you hit it, wait for the daily reset (midnight Pacific) before continuing a benchmark run.

## Known Limitations

- ChromaDB runs in-memory and is rebuilt from `data/docs/` on every process start; it is not persisted between runs.
- Token usage (`tokens.py`) is tracked in-memory for the current session only.
